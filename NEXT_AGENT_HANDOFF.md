Two client defects were found and fixed during staging verification. `GET /api/me` returns privacy-preserving `RoomListing` summaries that omit `members`; `canViewRoom()` dereferenced `room.members.some(...)`, and the room list is computed on every render, so the first listing threw `TypeError: Cannot read properties of undefined (reading 'some')` and unmounted the app to a blank page. `canViewRoom()` now treats a listing without a `members` array as viewable (the server already scoped it to the caller) while still rejecting blocked users, and an `AppErrorBoundary` plus an "arena unavailable" fallback replace the blank page. Separately, the client opened `/ws` without the required `?room=` query, so every handshake returned 404 while HTTP polling hid the failure; a tested `socketUrl()` helper now includes the room code.
