# Clerk readiness review

The existing SDK generation and React controls were preserved. Added a dedicated Clerk development launcher rather than changing local-profile development behavior. It loads `.env.local` only at runtime without printing it, accepts development keys, derives the trusted issuer, supplies exact authorized origins, rejects occupied ports, disables local identities and keeps a separate local database and frontend bundle.

The API continues using the installed Clerk verifyToken implementation. It now supports a configured issuer and optional PEM public key, refuses an empty/wildcard origin allowlist, requires nonempty user/session identities, and rejects pending sessions. Detailed verifier failures and tokens are not returned to clients. Subject-based ownership remains the authorization boundary. Profile-name projection is still deferred; absent verified name claims display as Auction fan.

Seventeen new tests use ephemeral RSA keys and actual Clerk SDK verification, covering valid and forged signatures, tampered subjects, expired/future claims, wrong/missing authorized parties, wrong issuer, missing session/empty subject, pending sessions, separate verified identities' private rooms, disabled local identities, and launcher configuration. These are cryptographic/local HTTP-boundary tests; they do not establish successful browser sign-in with Clerk.

Regression checks passed: TypeScript, 40 core tests total, 76 local tests and four selected Playwright desktop/mobile lifecycle and management journeys. The six full local E2E scenarios from the prior completion milestone remain separate evidence. The new browser-results.json records the four scoped regression cases.

The user supplied host-side CLI diagnostics confirming Wrapper is linked and reachable with development keys in .env.local. Secret keys were not read or printed by the agent. The actual-key launcher built the frontend and served API health/config correctly, with local profile sign-in disabled. The unauthenticated me route returned 401.

The agent environment denied outbound HTTPS to Clerk's public signing-key endpoint with EACCES; the agent preview was stopped. Live verification subsequently passed through the authorized host helper: room 139DCB, actual AuctionArena heading, real ticket session/API subject, create/claim/reload and sign-out with private access returning 401. The helper created one synthetic development user/session, retained the user/room, signed out and closed its own preview. See ../WP1-CLERK-LIVE/result.json and its screenshots. No AWS or production resources were changed; password/OTP/OAuth/MFA and live multi-user/mobile Clerk coverage remain unverified.
