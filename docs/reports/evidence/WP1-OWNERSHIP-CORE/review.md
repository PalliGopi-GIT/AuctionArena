# Ownership core implementation notes — independent review pending

The new coordinator implements the provider-independent portion of root architecture §5.2. The testkit provides explicit atomic models rather than relying on the single-process file adapter. No deployed or real datastore guarantee follows from these models.

Acquisition requires an atomic absent lease, a durable epoch compare/increment and a successful same-token renewal after that durable round trip. Each acquisition has a fresh token. Request-start monotonic time bounds local ownership, independently of the wall-clock auction deadline. Token-conditional release cannot remove another owner. Explicit release invalidates admission immediately, including operations waiting on I/O.

Every write passes its epoch/token and expected version to the durable port. Proposals serialize and are cloned before queueing. A stale epoch demotes; a version conflict returns without reapplying against different state. An uncertain commit demotes and returns TIMEOUT_RETRY without an automatic retry or success receipt. The adapter contract requires entity mutations, events, idempotency, timers and outbox work to share a conditional transaction. It does not introduce a whole-room database item.

The 20 new cases cover contention, token-safe cleanup, expiry/renewal, delayed responses, lost coordination keys, stale in-flight transactions, uncertain success, conflicting versions, queued proposal mutation, release during acquisition/write and invalid clocks/responses. The real-engine case commits a bid, reelects after its deadline and verifies stale direct-write rejection, the preserved deadline, one sale, the winner's purchase and its exact budget deduction. These are model tests, not a process-kill or cloud drill.
