# Two-user Clerk auction review

The new typed flow uses two new synthetic development users and one private room. The running instance must match the selected development instance. The host and guest have separate browser contexts; the host tab also signs out, activates the guest identity before it has membership, checks private denial, and returns to the host identity. A new invite is explicitly issued after returning to the host; cleared credentials from an old identity are not reused by the UI.

Assertions cover room-list filtering, denied private read and WebSocket ticket, invalid/valid invitation, distinct claims, readiness, host-only start, guest bid, one settled purchase, exact balances/squad, real WebSocket RESULT delivery to both browsers, completed results, reload and signed-out private denial. Browser errors fail the flow. Persistent reports contain bounded outcomes, not tokens. Failure screenshots mask inputs. No personal accounts are used or altered.

The UI correction clears old private interaction state on identity changes and guards room/list rendering against current membership before passive effects run. Unit coverage checks member/nonmember/signed-out/blocked behavior and clearing all invitation keys while preserving unrelated tab state. Desktop/mobile browser coverage tests actual local sign-out/new-profile behavior, invite removal, route clearing, room-list isolation and server denial.

No additional users/rooms are provisioned. Fixture guards have regression coverage for incomplete reports, changed identities, joined/started/purchased rooms and altered settings.
