# Accessibility implementation and audit boundaries

The local interface now has a keyboard skip link and focusable main landmark, mobile primary navigation, selected room-section state, an inert background behind app dialogs, authored 44px controls and checkbox-label hit areas, safer narrow form grids and wrapping for long room names. Result totals are a named section and the completion explanation is a note. Decorative logo glyphs no longer affect the natural brand name. Two low-contrast avatar labels were corrected. Disabled mobile bid controls no longer float over the timer; enabled controls retain their sticky behavior.

Shared auction announcements now use a dedicated React component and pure scheduler. Polite updates coalesce on a one-second window. Critical pause, sale/unsold and connection messages are spaced by at least two seconds. Timer warnings occur at 10/5-second thresholds rather than every tick. Transient disconnection warnings cancel, spoken stale connection/pause text clears on recovery, reconnecting into a paused room announces its current state, and pending private messages cancel on room exit/modal isolation. Previous raw status announcements and duplicate successful-bid toasts were removed. Rejection alerts remain local to the sender. No API calls or authoritative room-state mutations were added.

React review: component state holds only live-region text; the scheduler is per mounted component and timers clean up on unmount/exit; effects have explicit state dependencies; there are no new subscriptions, fetch waterfalls, raw HTML or provider keys in the client. Axe is a development dependency used only by tests. Shared browser helpers were moved to helpers.ts without changing their product-driven create/join flow.

Axe 4.14.0 scans sixteen states on each of desktop and mobile Chromium: home, local sign-in, create settings/review, lobby, squads, player pool, members, history, edit rules, live leading bid, paused state, end confirmation, completed results, manual result copying and room list. The baseline captured contrast, heading order and label/content findings. Corrected scans report zero violations with WCAG A/AA tags and best-practice checks; no rules or selectors were disabled. Raw baseline/final sanitized reports retain rule IDs, selectors and summaries without provider credentials or invitation secrets.

Zero automated violations is not a complete accessibility or WCAG-conformance result. Axe incomplete checks remain in both reports: these include decorative transparent logo/art lettering and contrast it cannot determine over gradients or overlapping/clipped elements. Decorative glyphs were source-reviewed, while remaining contrast/obscuration checks need human review. Human screen-reader output, OS/browser zoom, real touch devices, Safari and third-party Clerk challenge UI have not been verified. Keyboard, modal focus, accessible names and 320-CSS-pixel reflow have explicit browser assertions; these are not a replacement for assistive-technology user testing.

Eight deterministic announcement tests and all 78 core tests pass. The full browser invocation passed all 20 auction cases and both scan matrices. Its two keyboard cases stopped on an incorrect no-space brand-name expectation. Chrome's natural Auction Arena name is valid; the corrected expression accepts normalized whitespace. Both keyboard cases then passed, including extra home scans, skip visibility and clearing announcement text on view exit/sign-out. validation.json composes the 24 verified cases while preserving the raw full-run count (22 pass, 2 assertion failures) and separate corrected rerun (2 pass). No clean single-run result is fabricated. Production build and owned-server cleanup passed. Full-page screenshots supplement viewport/focus assertions; offscreen fixed content in beyond-viewport captures is not a substitute for those assertions.

Prior live Clerk fixtures are untouched. The host-installed axe package also produced an npm audit with seven affected package entries (2 critical, 1 high, 4 moderate). dependency-audit.json retains installed versions/advisory links. Remediation is a separate planned compatibility-tested task, WP1-DEPENDENCY-HARDENING; no force update or production-security pass is claimed.

Sources: [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing), [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [minimum contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), [44px enhanced target criterion](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced). The project independently requires 44px targets; this is not a claim that all enhanced WCAG criteria are met.
