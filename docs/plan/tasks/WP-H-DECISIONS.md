# WP-H Decisions

Every judgment call, with what/why/alternative rejected.

| # | Date | Decision | Why | Alternative rejected |
|---|------|----------|-----|----------------------|
| 1 | 2026-11-19 | Treat `WP-H-PROMPT.md` as the authority; re-read before each phase | Required by the prompt | Relying on conversation memory |
| 2 | 2026-11-19 | Use `Assets/ipl_player_pool_250_clean.csv` | It is the only CSV in `Assets` | Any copy outside `Assets` |
| 3 | 2026-11-19 | No `manifest.csv` exists. Bundle owner-supplied photos with `license: UNRECORDED`, `provenance: owner-supplied`, and show the gap in the Image credits view | The objective requires real player photos, and the owner explicitly supplied this folder; refusing every photo would defeat the feature. The gap is visible and reversible | (a) Fallback for every photo: obeys the license rule literally but fails the objective; (b) invent a license: unsafe |
| 4 | 2026-11-19 | `marquee = tier === 'A'` | Deterministic derivation from real data; no invented curated list | A hand-picked marquee list (subjective, invented) |
| 5 | 2026-11-19 | No team logo matches; use generated crests | Team IDs are `t1`–`t8` and names are fictional; logo files are real IPL abbreviations. Matching by city would be a guess | Renaming teams or guessing a city map (both prohibited) |
| 6 | 2026-11-19 | Catalog players have no career stats; show "Career statistics unavailable" | CSV has no stats; zeros would be invented | Fabricated stats |
| 7 | 2026-11-19 | Convert PNG photos to 640 px WebP with the locally installed Chrome via Playwright | No ImageMagick/ffmpeg/sharp available and downloads are prohibited. Chrome is already installed for E2E | Copying PNG bytes under a `.webp` name (wrong content type) |
| 8 | 2026-11-19 | Keep `createRoom()` defaulting to `samplePlayers()`; only a previewed/approved plan swaps in catalog players | Preserves every legacy room and the existing core test fixtures; rooms without a plan keep working, as required | Making every room catalog-backed at creation (breaks legacy fixtures and many tests) |
| 9 | 2026-11-19 | Persist the plan as additive JSON on `Room`; no SQLite table migration | Both adapters already round-trip the room object; the change is backward compatible. Parity is proven by tests | A new `room_plan` table (more surface, no benefit) |
| 10 | 2026-11-19 | Plan order lives in `orderedPlayerIds`; `Room.players` stays in catalog order and `openNext` follows the plan | Prevents participants from inferring the order from the player array; existing `currentPlayerIndex` consumers keep working | Reordering `Room.players` to the plan (leaks the order in every snapshot) |
| 11 | 2026-11-19 | `start` auto-approves the pending previewed plan | Preserves the existing "Start auction" button and tests while making approval the start gate | A second start button or a hard error for legacy callers |
| 12 | 2026-11-19 | Plan preview auto-runs for the host when the lobby opens (Standard by default) | The host sees a preview immediately; Standard is the required default | Requiring an extra click before any preview exists |
| 13 | 2026-11-19 | Do not change the legacy `minSquad * teamCount <= 24` guard | Squad rules are explicitly out of scope; the new pools exceed it easily | Relaxing it to the catalog size (a rule change) |
| 14 | 2026-11-19 | Persist the approved order in `orderedPlayerIds` and track progress with `planPosition`; keep `Room.players` in catalog order | Snapshots expose `players`; reordering them would leak the upcoming order to participants. `currentPlayerIndex` still points at the current lot, so existing consumers keep working | Reordering `Room.players` to the plan order (order leak) |
| 15 | 2026-11-19 | Approval replaces `Room.players` with the selected pool in catalog order | The live UI, CSV and results need player records for the pool, but not in auction order. Legacy rooms without a plan keep their original players | Keeping the sample pool and resolving catalog records on the fly (more lookups, more failure modes) |
| 16 | 2026-11-19 | The server generates and injects the seed in the local store and Durable Object after fingerprinting the client action | The client must not choose the seed, and retries must remain idempotent. The fingerprint uses the original payload so a retry is not seen as a different action | Accepting a client seed (insecure) or fingerprinting after injection (retries become ID_REUSED) |
| 17 | 2026-11-19 | Number repeated set names ("Balanced Mix 2") instead of repeating a label | Set names are shown to participants and used as CSV labels; duplicate names are ambiguous | Repeated Roman numerals or duplicate names |
| 18 | 2026-11-19 | A role-wise set is pure only when the role queue can fill the whole set; otherwise it stays mixed | Avoids fabricating a pure set from too few players and keeps the three-run cap satisfiable | Forcing a pure set and violating the run cap |
| 19 | 2026-11-19 | Repair mixed rosters with same-tier role swaps after tier spreading | Tier spreading can stack a role; swapping same-tier players preserves quotas while making the three-run cap feasible | Relaxing the cap or changing quotas |
| 20 | 2026-11-19 | No unsold recall was added | The current engine has no recall feature and the prompt says to keep existing behavior and not add features. Unsold lots remain terminal and are visible in results | Inventing a recall flow (scope violation) |
| 21 | 2026-11-19 | Team crests are generated from team colours and initials; no logo files are served | No logo matched the fictional team identities by ID or exact name; guessing a city map is prohibited | Renaming teams or guessing matches |
| 22 | 2026-11-19 | 21 supplied `.png` files that are byte-identical SVG placeholders are marked `unconverted` and use the initials avatar | They are not photographs; bundling them as photos would misrepresent the assets. The condition is recorded in the manifest and credits | Bundling placeholder SVGs as player photos |
| 23 | 2026-11-19 | The host lobby auto-previews Standard, but room creation itself does not persist a plan | New UI rooms get the catalog flow immediately while direct engine/store callers and legacy rooms keep their existing behavior. Approval remains explicit | Persisting a plan at creation (would break legacy tests and make the preview less honest) |
| 24 | 2026-11-19 | E2E specs derive the current lot and base price from server state instead of hardcoding `p1` / ₹100 | New rooms now start a seeded catalog plan, so the first lot varies. Deriving keeps the tests meaningful without weakening them | Disabling the catalog flow for tests (would not test the feature) |
| 25 | 2026-11-19 | Run browser, restart and load checks in an isolated copy with a fresh `AA_EVIDENCE_DIR` | Required by the prompt; protects the owner's private data and earlier evidence | Running against the working tree's `.data` and existing evidence |
| 26 | 2026-11-19 | Preview/approve/export responses are host-only; participants receive only the derived `planSummary` | Required order privacy. The summary exposes the current set name/index and remaining counts, never IDs or the seed | Including the plan in every snapshot (order leak and size risk) |
| 27 | 2026-11-19 | Allow the host to export a draft CSV before approval, not only the approved order | Approval starts the auction and unmounts the plan panel, so a post-approval-only export would be unreachable from setup. The draft is rendered from the catalog, the approved order from `room.players`; both remain host-only | Removing draft export (the host could no longer review the order before committing) |
| 28 | 2026-11-19 | Add a host-only "Export order" control to the live arena toolbar | Keeps approved-plan CSV export reachable after the plan panel unmounts, without exposing it to participants | A second setup-only export or no export after start |
| 29 | 2026-11-19 | Intercept the room socket with the regex `/\/ws/` in the ACCOUNT_DELETED test | Playwright's `page.routeWebSocket('**/ws')` does not match `ws://.../ws?room=...`, so the test silently missed the socket | A wildcard pattern that does not match the query string |
| 30 | 2026-11-19 | Derive the older-history page size by paging `/api/rooms/:code/history` in `local-bounds.spec.ts` | The host lobby now auto-previews a plan, adding a `plan_previewed` event; the old hardcoded `11` was stale. Paging the API keeps the assertion exact without weakening it | Hardcoding a new count that would break again when another event is added |
| 31 | 2026-11-19 | Add a Mega opening-set browser case and assert every opening lot ID against the approved order | The prompt asks for each mode to be previewed/approved and for the live sequence to equal the approved order. The added case closes that gap on desktop and mobile without running all 250 lots | Relying on planner/unit tests alone for Mega and checking only sold counts |
